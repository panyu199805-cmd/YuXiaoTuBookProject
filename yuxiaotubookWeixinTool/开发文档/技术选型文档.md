## 一、选型结论（1 分钟读完）

| 维度 | 定版方案 |
|------|----------|
| **小程序框架** | **uni-app（Vue 3 + TypeScript + Pinia）** |
| **构建工具** | Vite（uni-app 官方 Vue3/Vite 模板） |
| **UI 组件** | uni-ui + 自定义组件（对齐 Web 品牌色 `#5b9aa0`） |
| **HTTP** | `uni.request` 封装，与 Web `api/client.ts` 同构 |
| **后端** | **零新增**：复用 `www.yuxiaotubook.com` Python + Java API |
| **Admin** | **零新增**：继续用现有 Vue3 Admin，不改小程序仓库 |
| **状态管理** | Pinia（user / site 与 Web stores 同构） |
| **登录** | 一期 JWT 账号密码；二期微信 code2session |
| **支付** | 一期 mock-pay；二期微信支付 + Java trade 扩展 |

**定版一句话：**

> 用 uni-app Vue3 复刻 Web 用户端页面与 Pinia/API 层，100% 复用现有后端与 Admin，仅增加小程序壳与微信能力适配。

## 二、框架选型对比

### 2.1 候选方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| **uni-app Vue3** | 与 Web 同 Vue3/Pinia；TS 支持好；一套代码可扩 H5 | 包体略大于原生；部分 API 需条件编译 | **选用** |
| 原生微信小程序 + TS | 性能最优、官方支持最全 | 与 Web 无法共享组件；双份 UI 维护成本高 | 不选 |
| Taro React | 生态大 | 与现有 Vue3 技术栈割裂 | 不选 |
| 微信云开发 | 免运维 | 与现有 MySQL/FastAPI 架构冲突；数据不同源 | **不选** |

### 2.2 选择 uni-app 的理由

1. **团队已有 Vue 3 + Pinia 经验**（Web 前端 `YuXiaotuBook/frontend`）
2. **API 层、Store、工具函数可高度复用**（`protectVideoUrl`、`resolveMediaUrl` 等）
3. **页面结构 1:1 映射** Web views，降低设计与联调成本
4. **条件编译** 可处理 `wx.login`、`<video>` 等平台差异
5. **H5 编译** 便于开发期浏览器调试（可选）

## 四、技术栈明细

### 4.1 前端（小程序工程）

| 类别 | 选型 | 版本建议 |
|------|------|----------|
| 框架 | uni-app | 最新 stable（Vue3 模式） |
| 语言 | TypeScript | ≥ 5.0 |
| 构建 | Vite | 随 uni-app 模板 |
| 状态 | Pinia | ≥ 2.1 |
| 样式 | SCSS + CSS 变量 | 对齐 Web `--color-primary` 等 |
| 代码规范 | ESLint + Prettier | 与 Web 项目一致 |
| 包管理 | pnpm | 与 monorepo 习惯一致 |

### 4.2 后端（复用，不新建）

| 服务 | 技术 | 小程序调用方式 |
|------|------|----------------|
| 内容/用户 API | Python FastAPI | `https://www.yuxiaotubook.com/api/v1/...` |
| 交易 API | Java Spring Boot | 同上路径，Nginx 已分流 |
| 媒体 | Nginx + `/media/v/` | 小程序 `<video src>` 合法域名 |
| 认证 | JWT HS256 | Header `Authorization: Bearer` |

### 4.3 与 Web 共享逻辑（建议抽离或复制）

| 模块 | Web 路径 | 小程序路径（规划） |
|------|----------|-------------------|
| 视频 URL 保护 | `frontend/src/utils/video.ts` | `src/utils/video.ts` |
| 媒体 URL 解析 | `frontend/src/utils/media.ts` | `src/utils/media.ts` |
| API 响应类型 | 各 view 内联 | `src/types/api.ts` 统一 |
| site store | `stores/site.ts` | `stores/site.ts` |
| user store | `stores/user.ts` | `stores/user.ts` |

**远期可选：** 在 monorepo 根目录建 `packages/shared`，Web 与小程序共同引用。一期先 **复制 + 注释同步**，降低改造 Web 的风险。

## 五、网络与域名配置

### 5.1 微信公众平台需配置

| 配置项 | 域名 |
|--------|------|
| request 合法域名 | `https://www.yuxiaotubook.com` |
| uploadFile 合法域名 | 同上（若一期不上传可暂不配） |
| downloadFile 合法域名 | 同上 |
| 业务域名（WebView 用户协议） | `https://www.yuxiaotubook.com` |

### 5.2 API BaseURL

```typescript
// 开发
const DEV_BASE = 'http://127.0.0.1:8000/api/v1'  // 微信开发者工具勾选「不校验合法域名」

// 生产
const PROD_BASE = 'https://www.yuxiaotubook.com/api/v1'
```

Java 订单/会员路径与 Web 相同，**无需单独 baseURL**（Nginx 统一入口）。

### 5.3 媒体 URL 拼接

```text
封面：  https://www.yuxiaotubook.com/uploads/...
占位：  https://www.yuxiaotubook.com/placeholders/books/xxx.svg
视频：  https://www.yuxiaotubook.com/media/v/bookReview/{basename}
首页视频：https://www.yuxiaotubook.com/media/v/homePage/{basename}
```

小程序 `<image>` / `<video>` 必须使用 **完整 HTTPS URL**（不可相对路径）。

## 六、关键能力适配

### 6.1 认证

| 阶段 | 方案 |
|------|------|
| 一期 | `POST /auth/login`，token → `uni.setStorageSync('token')` |
| 二期 | `wx.login` → 后端 `POST /auth/wechat-login { code }` → 绑定 openid，返回 JWT |

**后端二期需新增（规划，不在一期范围）：**

- `users.wechat_openid` 字段
- 微信登录接口（Python FastAPI）

### 6.2 视频播放

| 场景 | 方案 |
|------|------|
| 书籍解读 | 原生 `<video>`，`controls`，试看逻辑与 Web VideoPlayer 一致 |
| 首页背景 | `<video>` muted loop；双图层 crossfade 简化版 |
| 性能 | 服务端 ffmpeg 720p + faststart；小程序 `preload="metadata"` |

**不建议一期使用 HLS**：现有 API 直出 mp4，Nginx Range 已支持；HLS 需额外转码与 m3u8 端点。

### 6.3 支付

| 阶段 | 方案 |
|------|------|
| 一期 | `mock-pay`（与 Web 一致，适合内测） |
| 二期 | Java `POST /member/orders/{id}/pay` 对接微信支付；小程序 `wx.requestPayment` |

### 6.4 电子书阅读

- 一期：长文本 `scroll-view` + 分段样式（标题/步骤）
- 字号、主题切换用本地 Storage
- 不引入 heavy markdown 渲染库；内容来自 `ebook_content` 纯文本/简单 Markdown

### 6.5 分享

```javascript
onShareAppMessage() {
  return {
    title: book.title,
    path: `/pages/book/detail?id=${book.id}`,
    imageUrl: resolveMediaUrl(book.cover)
  }
}
```

## 七、与 Admin / Web 的数据一致性保障

| 机制 | 说明 |
|------|------|
| **无小程序本地 CMS** | 所有内容字段来自 API，不做离线内容包 |
| **site store 启动拉取** | `App.onLaunch` → `GET /site/config`（同 Web `main.ts`） |
| **详情页强制 network** | 书籍详情每次 `onShow` 可 refresh（可选下拉刷新） |
| **版本号无关内容** | Admin 改库即生效，不依赖小程序发版 |
| **用户态共享** | 同一 JWT 语义，同一 `users` / `user_book_collect` 表 |

**注意：** 小程序发版仅影响 **UI 与客户端逻辑**；内容、价格、视频 URL 均由服务端驱动。

## 十一、安全清单

- [ ] HTTPS only
- [ ] Token 不打印到 console（生产）
- [ ] 敏感配置走 `manifest.json` + 环境变量，不进 Git
- [ ] 视频域名校验，禁止任意 URL 注入
- [ ] 用户输入 XSS：电子书内容仅 text 渲染，不用 rich-text 解析不可信 HTML
